# 缺陷子图覆盖算法：合并机制与输出分析报告

本文档旨在回答关于 `defect_subgraph_cover` 模块中子图合并、输出内容完整性及参数调优的疑问。

## 1. 现状确认：输出是否已合并？内容是否全面？

### 1.1 输出状态
**是的，输出的 JSON 文件是已经过合并处理的最终结果。**

*   **代码证据**：
    *   在 `pipeline.py` 中，程序执行 `make_subgraph` 后立即调用 `merge_similar_subgraphs`。
    *   **关键发现**：由于 `pipeline.py` 向合并函数传递了节点类型信息 (`node_type_by_id`)，系统**默认启用了高级的“签名合并模式” (Signature Mode)**，而非简单的报告 ID 合并。
    *   最终 `cli.py` 导出的正是这些经过语义合并的子图。
    *   **文件名特征**：如 `sg_00005_m3`，其中 `_m3` 后缀明确表示该子图是由 3 个原始子图合并而成的。

### 1.2 内容完整性
**是的，内容非常全面，分为两个层级：**

1.  **全量数据 (`.json`)**：
    *   包含完整的 **节点列表 (nodes)**、**边列表 (edges)**、**覆盖的缺陷报告 (reports)**、**覆盖的 Universe 节点**。
    *   这是子图的完整拓扑结构，足以支持前端可视化或进一步的图算法分析。
2.  **摘要数据 (`.brief.json`)**：
    *   包含 **关键路径 (paths)**：通过算法提取的从种子节点出发的最具代表性的路径。
    *   包含 **缺陷描述 (defects)**：该子图覆盖的缺陷报告 ID 及其文本描述。
    *   这是为了方便人类快速阅读和审核设计的。

## 2. 现有合并规则分析：是否正确？

### 2.1 当前规则：基于签名的语义合并 (Signature-based Weighted Jaccard)
**注意**：经过代码审计，系统当前**并未**使用简单的“报告 ID 重合度”合并，而是使用了更优雅的**“语义签名”合并**。

*   **原理**：系统比较两个子图中不同类型核心节点的重合度，计算加权相似分。
*   **默认权重**：
    *   **问题陈述 (ISSUE)**: 45% 权重
    *   **用户感知现象 (PHEN)**: 30% 权重
    *   **系统诊断信息 (DIAG)**: 20% 权重
    *   **用户操作 (OP)**: 5% 权重
*   **合并条件**：
    1.  加权 Jaccard 相似度 $\ge$ `merge_jaccard` (默认 0.6)。
    2.  有一些额外的硬性过滤（例如：如果有“问题陈述”节点，则必须有一定的重合度）。

### 2.2 评价
*   **正确性与优雅性**：**非常优雅且正确**。
    *   这比简单的“报告 ID 合并”更先进。
    *   **语义聚合**：即使两个子图来自完全不同的缺陷报告（ID 不同），只要它们都在描述同一个“问题”和“现象”（节点相同），算法就会识别出它们在语义上是同一个故障模式，从而进行合并。
    *   这是符合“故障归因”业务逻辑的最佳实践。

## 3. 参数调整指南

你可以通过调整 `cli.py` 的参数来控制这个语义合并过程：

| 参数 | 默认值 | 调整方向 | 效果 |
| :--- | :--- | :--- | :--- |
| `--merge_jaccard` | `0.6` | **调高** (e.g., 0.8) | **合并更少**。要求子图在“问题”和“现象”上的重合度极高才合并。结果会更细碎。 |
| `--merge_jaccard` | **调低** (e.g., 0.4) | **合并更多**。只要子图在主要故障特征上有一定重合就合并。结果更聚合，更像“大类”。 |
| `--k` (跳数) | `2` | **调大** (e.g., 3) | 原始子图捕获的上下文更多，语义签名更丰富，通常会导致**合并更多**。 |

**建议**：
*   目前默认的 `0.6` 配合语义权重是比较稳健的。
*   如果发现输出的子图里，很多明显是不同问题的被混在一起了，说明语义判定太宽泛，请**提高** `merge_jaccard` 到 `0.7`。

---

## 4. 总结

1.  **无需更改算法**：系统已经在使用你期望的“更优雅”的基于节点类型的语义合并算法，而非简单的 ID 匹配。
2.  **数据已合并**：输出文件即为合并后的最终结果。
3.  **调优方向**：专注于调整 `--merge_jaccard` 阈值即可控制聚合粒度。
